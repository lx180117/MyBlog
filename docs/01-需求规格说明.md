## 1. 项目定位

一个**多作者协作的 Markdown 内容发布平台**。从「个人博客」升级为「小团队/多人博客站」，核心诉求排序：

1. **多人可协作** —— 每个作者用自己的账号登录，各写各的，互不干扰。
2. **写作顺畅** —— 作者只专注 Markdown，排版、目录、代码高亮自动完成。
3. **访问体验好** —— 移动端可读、首屏快、支持暗黑模式。
4. **被搜索引擎收录** —— 具备基础 SEO 能力（meta、sitemap、RSS、SSR）。
5. **运营成本低** —— 部署在自有服务器上，软件全部开源，新增月成本为 0。

非目标：不做社区化运营（私信/积分/打赏）、不做电商、不做多租户 SaaS、不做无限层级评论。

## 2. 角色与权限

采用**两级角色**模型，权限边界清晰，不做细粒度 RBAC。

| 角色 | 说明 | 权限范围 |
| --- | --- | --- |
| 访客 Visitor | 未登录用户 | 浏览文章、按分类/标签筛选、搜索、提交评论（填昵称） |
| 作者 Author | 注册并通过审核的用户 | 访客全部权限 + 登录 + 写/改/删**自己**的文章、管理自己文章的评论 |
| 管理员 Admin | 站点负责人 | 全站配置、用户审核与禁用、分类维护、评论审核、全部文章的读写、数据统计 |

### 权限矩阵

| 能力 | 访客 | 作者 | 管理员 |
| --- | :---: | :---: | :---: |
| 浏览/搜索文章 | ✅ | ✅ | ✅ |
| 提交评论 | ✅ | ✅ | ✅ |
| 发表文章 | ❌ | ✅（仅自己的） | ✅（全部） |
| 编辑/删除他人文章 | ❌ | ❌ | ✅ |
| 查看他人草稿 | ❌ | ❌ `[默认]` | ✅ |
| 自由创建标签 | ❌ | ✅ | ✅ |
| 维护分类 | ❌ | ❌ `[默认]` | ✅ |
| 审核/删除任意评论 | ❌ | ❌ | ✅ |
| 用户审核与禁用 | ❌ | ❌ | ✅ |
| 站点设置 | ❌ | ❌ | ✅ |

`[默认]` **草稿完全私有**：只有作者本人和管理员能看到，作者之间互相看不到草稿。这是最不容易出事故的默认值。

## 3. 功能需求

### FR-1 账号与认证（多作者模式的核心）

- **FR-1.1 开放自助注册**：注册需填用户名（唯一）、邮箱（唯一）、密码。密码强度校验（≥ 8 位，含字母与数字）。
- **FR-1.2 注册后需管理员激活**：注册成功即为 `pending` 状态，可登录但不能发文；管理员在后台审核通过后变为 `active`。
- **FR-1.3 登录**：支持用户名或邮箱 + 密码登录。JWT 双 Token（Access 短时效 + Refresh 长时效）。
- **FR-1.4 个人资料**：昵称、头像、个人简介、社交/外链（GitHub、主页等）。
- **FR-1.5 作者主页**：`/author/{username}` 展示该作者的公开文章列表与简介。
- **FR-1.6 账号状态机**：`pending 待审核 → active 正常 → disabled 禁用`，三态由管理员控制。
- **FR-1.7 安全防护**：登录失败次数限制与短时锁定；密码使用 argon2 哈希。
- **FR-1.8 密码找回**：`[默认]` v1 不接邮件服务，忘记密码由管理员后台重置；邮件自助找回列入 v1.1。

### FR-2 文章内容管理

- **FR-2.1** 文章字段：标题、正文（Markdown）、封面图、摘要、状态、发布时间、置顶标记。
- **FR-2.2** **文章归属作者**：数据库强制记录 `author_id`；作者只能操作自己的文章，管理员可操作全部。
- **FR-2.3** 状态流转：`草稿 draft → 已发布 published → 回收站 deleted`（软删除，可恢复）。
- **FR-2.4** Markdown 编辑体验：源码 + 实时预览、代码块语法高亮、图片粘贴上传、常用快捷键。
- **FR-2.5** 定时发布：指定未来时间，到点自动转已发布。
- **FR-2.6** 摘要自动生成：未填写时从正文截取前 N 字。
- **FR-2.7** 置顶：管理员可置顶任意文章，作者可置顶自己的。
- **FR-2.8**（v1.1 可选）文章转让给其他作者 / 版本历史回滚。

### FR-3 分类与标签

- **FR-3.1** 分类：单层级，一篇文章归属**一个**分类；`[默认]` 分类由**管理员统一维护**，作者只能选用，防止分类被写乱。
- **FR-3.2** 标签：多对多，作者可自由创建新标签；后台提供标签合并与清理。
- **FR-3.3** 归档视图：按年 / 月聚合的时间线。
- **FR-3.4** 分类页、标签页均有独立列表页，支持分页。

### FR-4 评论与互动

- **FR-4.1** 评论提交：`[默认]` 登录用户评论自动关联账号（昵称+头像取自资料）；同时允许访客填昵称评论，便于外部读者互动。
- **FR-4.2** 两级结构：评论 + 对评论的回复，不做无限嵌套。
- **FR-4.3** 审核流：`待审核 pending / 已通过 approved / 已拒绝 rejected`，`[默认]` 新评论一律待审核。
- **FR-4.4** 反垃圾：同 IP 提交频率限制、简易敏感词过滤。
- **FR-4.5** 作者可查看并管理自己文章下的评论。
- **FR-4.6** 文章点赞：单篇维度计数，`[默认]` 按 IP + 文章去重。

### FR-5 检索

- **FR-5.1** 关键词搜索：覆盖标题与正文。
- **FR-5.2** 结果分页、按分类/标签筛选、按发布时间或热度排序。
- **FR-5.3** `[默认]` 使用**数据库原生全文检索**实现，不引入独立搜索引擎（省掉一个需要运维的中间件）。

### FR-6 后台管理

- **FR-6.1** 仪表盘：文章总数、作者数、待审用户数、待审评论数、阅读量趋势（近 7 / 30 天）。
- **FR-6.2** 用户管理：审核注册申请、启用/禁用账号、后台重置密码。
- **FR-6.3** 内容管理：全部文章列表（可按作者筛选）、分类管理、标签管理。
- **FR-6.4** 评论管理：批量通过、拒绝、删除。
- **FR-6.5** 站点设置：站点名、Logo、备案信息、社交链接、每页文章数、评论开关、是否开放注册。

### FR-7 站点展示与 SEO

- **FR-7.1** 前台页面：首页文章流、文章详情页、分类页、标签页、归档页、搜索页、**作者主页**、关于页。
- **FR-7.2** 文章详情页展示：作者头像与昵称（可点击进作者主页）、发布时间、阅读量、分类、标签、目录（TOC）。
- **FR-7.3** 响应式布局：桌面 / 平板 / 手机三档。
- **FR-7.4** 暗黑模式：跟随系统 + 手动切换。
- **FR-7.5** SEO：每页 `title`/`description`、文章页 Open Graph、`sitemap.xml`、`robots.txt`、**服务端渲染（SSR）保证可被收录**。
- **FR-7.6** RSS / Atom 订阅输出。
- **FR-7.7** 阅读量统计：单篇 PV 计数 + 简易访问日志。

## 4. 非功能需求

| 维度 | 指标 |
| --- | --- |
| 性能 | 列表接口 P95 < 300ms；首屏可交互 < 2s；列表分页每页 ≤ 20 条 |
| 安全 | 密码 argon2 哈希、JWT 校验与可失效、参数化查询、Markdown 渲染结果转义（防 XSS）、上传文件类型与大小校验、后台接口鉴权、作者只可操作自己的资源（越权校验） |
| 可维护 | 分层清晰（Controller / Service / Repository）、接口文档化（OpenAPI 3）、数据库变更走迁移脚本 |
| 可靠性 | 数据库每日自动备份；文章内容可导出为 Markdown |
| 成本 | 部署在**自有服务器**上，软件全部开源（MIT / Apache 2.0），**新增月成本 0 元** |
| 规模假设 | 作者 ≤ 20 人；文章 ≤ 1000 篇；评论 ≤ 1 万条；访问量 ≤ 1000 PV/日 |

## 5. 关键数据实体（Step 4 展开为 DDL）

| 实体 | 说明 | 主要关系 |
| --- | --- | --- |
| `user` | 账号：用户名、邮箱、密码哈希、昵称、头像、简介、社交链接、角色、状态 | 1 : N `article`；1 : N `comment` |
| `article` | 文章：标题、正文、摘要、封面、状态、发布时间、置顶、阅读数 | N : 1 `user`（作者）；N : 1 `category`；N : N `tag` |
| `category` | 分类（单层） | 1 : N `article` |
| `tag` | 标签 | N : N `article` |
| `article_tag` | 文章-标签关联（多对多中间表） | — |
| `comment` | 评论：作者可空（游客）、昵称、邮箱、内容、审核状态 | N : 1 `article`；N : 1 `user`（可空）；自关联 `parent_id` 实现两级回复 |
| `site_setting` | 站点配置（键值对） | 独立表 |
| `page_view` | 访问/阅读记录 | N : 1 `article` |
