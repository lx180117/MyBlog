## 二、渲染策略：SSR 与 CSR 的分界线

**为什么这样分**：前台要 SEO（爬虫必须拿到正文 HTML），后台首屏就带用户态、
且 token 存在浏览器 cookie 里 —— 服务端读不到，硬做 SSR 只会先渲染「未登录」
再被客户端覆盖，白闪一次还容易走错权限分支。

- 前台：SSR。文章详情页输出完整 HTML + JSON-LD，分页/筛选全部体现在 URL query 里，
  每一页都能被独立收录。
- 后台：`routeRules` 里对 `/dashboard/**`、`/admin/**`、`/login`、`/register`
  关闭 SSR（`ssr: false`），走 SPA。
- 文章详情页的 **身份相关字段**（`likedByMe` / `canEdit`）SSR 时拿不到，
  策略是「SSR 出正文 + 挂载后带令牌重取一次纠正按钮状态」——
  正文 HTML 不变，所以不会闪。阅读量上报放在挂载后异步发，不阻塞首屏。

## 三、样式：Element Plus 的隔离与主色对齐

两件事必须一起做，否则要么污染前台、要么后台和前台像两个站：

1. **CSS 隔离**。`elementPlus.importStyle: false`，改由 `layouts/console.vue` 手动
   `import 'element-plus/dist/index.css'`。Vite 会把它切进后台路由的异步 chunk。
   实测：前台公共 CSS 62 KB，后台 `console.css` 359 KB —— 前台读者不必为
   后台的组件库买单。
2. **主色对齐**。EP 由 `--el-color-primary` 推导出 light-3…9 / dark-2 一整套色阶，
   只改基础色会让 hover、浅底仍停在默认蓝。`main.css` 用 `color-mix()` 把整套色阶
   绑到品牌色上，暗色模式再覆盖一遍。
3. `defaultLocale: 'zh-cn'`。EP 默认英文，不改的话分页是 "Go to"、弹窗按钮是 OK/Cancel。

## 四、数据层

- **`useApi`**：统一 baseURL、自动带 Bearer、把 Nest 的错误体压成可展示的中文
  （`message` 是数组时合并成一行）。**401 自动刷新令牌并重放原请求**，且用
  `inflightRefresh` 保证同一时刻只有一次刷新在飞 —— 首屏并发五六个请求同时过期时，
  各自去换令牌会因为「refresh token 已被消费」把用户莫名踢下线。
- **缓存边界**（关键设计，避免「改了资料页面头没变」）：
  - `useAuth`：登录态与当前用户，改资料后统一更新全局 state；
  - `useSettings`：站点公开配置（前台几乎每页都要），保存后台设置后要
    **清缓存再拉一次**，否则站点名要等手动刷新才变；
  - `useTaxonomy`：分类 + 标签，后台增删后调 `loadTaxonomy(true)` 强制刷新，
    作者编辑器里的分类下拉随之更新。
- **`usePagedList`**：后台 8 个列表页共用的分页加载器，处理了两件容易漏的事——
  快速翻页的**响应竞态**（自增序号丢弃过期响应）、以及**删空当页后回退一页**
  （否则停在一个空白页上，用户以为数据没了）。

## 五、编辑器

- **预览用 marked 而不是 markdown-it**：后端 `renderMarkdown` 用的就是 marked
  （`gfm: true, breaks: false`）。解析器不同源的话，表格换行、任务列表、
  软换行处理的差异会让「预览」和「发布后」长得不一样。
- 预览渲染有 **220ms 防抖**：长文每敲一个字就全量重新高亮代码块会明显卡顿。
- 工具条插入语法基于原生 textarea 的 `selectionStart/End`（而不是 `el-input`
  的内部实例），插入后回写光标位置。
- 支持**粘贴截图直接上传**（写博客最常见的配图方式）。
- `Ctrl/⌘+S` 存草稿；有未保存修改时 `beforeunload` + 路由离开二次确认。
- 新建与编辑**共用同一个组件**，保存成功后 `router.replace` 换成编辑页 URL，
  内容不跳变。

## 六、权限与「URL 即状态」

- `middleware/auth.ts` 会先 `await restore()` 再判登录态。会话恢复在客户端插件里做，
  而插件与中间件的执行顺序不保证 —— 不 await 的话，「刷新页面」会把已登录用户
  弹到登录页（站内跳转却正常，极难查）。
- `middleware/admin.ts` 对非管理员**送回工作台**而不是登录页（他已经登录了，
  弹登录页会让人以为掉线）。
- 后台的筛选状态一律写进 URL（`?status=pending`）：仪表盘卡片可以直接链过来，
  刷新不丢条件，浏览器前进后退符合直觉。组件内部切标签也会把状态写回 URL，
  两边不会出现「界面显示 A、地址栏是 B」。
- **编辑页必须给 `definePageMeta({ key })`**：从「编辑 A」跳到「编辑 B」是同一个
  路由只换了参数，Nuxt 默认复用组件实例 —— 编辑器里还是 A 的内容而地址栏已经是 B，
  顺手保存就会把 B 覆盖成 A 的正文。同类页面（分类/标签/作者）一并加了 key。

## 七、契约一致性（Step 6 的核心）

前端类型不是手写的，而是从 `server/openapi.json` 生成：

```bash
cd server && npm run openapi:export   # 后端导出契约
cd client && npm run gen:api          # 生成 app/types/api.ts（59 个模型）
```

字段改动的唯一正确姿势是「改后端 DTO → 重新导出 → 重新生成」，
手改 `app/types/api.ts` 会在下次生成时被覆盖。

`npm run check:api` 补上类型系统管不到的那半边：`api.get('/me/articles')` 里的
路径只是普通字符串，写成 `/me/article` 一样能通过类型检查和构建，
只有点下去才 404。该脚本把「方法 + 路径」两边归一化（`{id}` / `${row.id}` → `:param`）
后比对，前端调用了契约里不存在的接口就**以非零码退出**。

`npm run verify` = typecheck + check:api，改完前端先跑这个。

3. 评论提交 → 审核 → 前台展示（含敏感词拦截与频率限制）；
4. 图片上传（文件头校验、大小上限、宽高回填）；
5. 令牌过期的自动刷新（含并发去重）。

补测方式：`cd server && npx prisma migrate dev && npm run seed && npm run start:dev`，

## 九、Step 7（墨刀原型 → UI 重构）时的注意点

- 设计系统的落点在两处：`app/assets/css/main.css` 的 `@theme`（品牌色板）与
  `@layer components`（`.card` / `.btn-primary` / `.field` / `.tag-chip` …）。
  **改视觉优先改这里**，不要在页面里散写颜色值。
- 后台的视觉改动要落在 EP 的 CSS 变量上（`--el-color-primary` 系列），
  而不是逐个组件覆盖样式。
- `paginate` 与筛选状态在 URL 里，重构时不要改成组件内部 state —— 会丢掉
  可分享链接和 SEO。
- 前台与后台是两套密度：前台偏阅读（行高 1.85、正文 16.5px），后台偏操作
  （EP 默认紧凑）。原型若只给一套，需要明确各自的应用范围。
